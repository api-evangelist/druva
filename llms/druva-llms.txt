By default the report provides the data for last 24 hours if no date/time filters are selected. For more information, see [guides on the Reports API](/docs/getting-started-with-reports-api).
- [Report IDs](https://developer.druva.com/reference/report-ids.md): This page provides the list of report IDs that you can select on the [Get Report](/reference/getreportdatarequest) API.
- [List Events](https://developer.druva.com/reference/listeventsrequest-1.md): This API returns a list of events based on pageToken or filters. <br>You can query using the pageToken or filters; you cannot provide both simultaneously. <br>When using the pageToken parameter, the initial request should not include any pageToken value. The response will contain a list of events and a nextPageToken. For subsequent API calls, include the pageToken parameter with the value of nextPageToken received from the previous API response. This ensures that you retrieve the next page of events. <br>For example   <br> /events?pageToken=qwwzsx1qwer0efjdvfhuvuvvuvu   <br> /events?pageSize=150&productID=12289&syslogSeverity=5

- [List all administrators](https://developer.druva.com/reference/listadminsrequest.md): Returns the details of existing administrators in the Cloud Console.   > 📘 Note   To use this API endpoint, enable the [Administrator API from Druva Cloud settings](/reference/administrators).
- [Create an administrator](https://developer.druva.com/reference/createadminrequest.md): Creates an administrator in the Druva Console.  > 📘 **Note**   To use this API endpoint, enable the [Administrator API from Druva Cloud settings](/reference/administrators).
- [Get administrator details](https://developer.druva.com/reference/getadminrequest.md): Returns the details of the specified administrator.   > 📘 **Note**   To use this API endpoint, enable the [Administrator API from Druva Cloud settings](/reference/administrators).
- [Delete an administrator](https://developer.druva.com/reference/deleteadminrequest.md): Deletes the specified administrator account from the Cloud Console.   > 📘 **Note**   To use this API endpoint, enable the [Administrator API from Druva Cloud settings](/reference/administrators  ).
- [Update administrator status](https://developer.druva.com/reference/updateadminrequest.md): Modify Administrator attributes, like Administrator Name, Timezone, and Status (either Active or Disabled).   > 📘 **Note**   To use this API endpoint, enable the [Administrator API from Druva Cloud settings](/reference/administrators).
- [Change an administrator's password](https://developer.druva.com/reference/changeadminpassword.md): Changes an adiminstrator's password.
- [Update administrator role](https://developer.druva.com/reference/updateadminrolerequest.md): Change the role and product-level access control configuration for the specified administrator. The request body must contain the complete desired role configuration. Any existing role settings not included in the request will be removed. <br>**Role behavior:** <br>- **Druva Cloud** - The administrator gets full access across all products. The productAccessControls field is ignored. <br>- **Product** - The productAccessControls field is required and defines per-product role and resource-level access. <br> <br>The available product roles and access controls applicable for a role can be fetched using the [List roles](/reference/listrolesrequest) API.   > 📘 **Note**   To use this API endpoint, enable the [Administrator API from Druva Cloud settings](/reference/administrators).
- [Activate Safe mode](https://developer.druva.com/reference/createsafemodeactivationsettings.md): This API initiates Safe Mode on your Cloud Console, imposing critical restrictions to mitigate active threats. It enables granular control by restricting administrator logins, blocking specified API credentials, and halting all backup operations, restores, and downloads.  * This operation requires API credentials with the Druva Cloud Administrator role.  * Safe Mode is activated immediately upon successful API call.
- [List all users](https://developer.druva.com/reference/get_usermanagement-v1-users.md): Returns the list of users in Druva inSync with their details.
- [Create a new user](https://developer.druva.com/reference/post_usermanagement-v1-users.md): Creates a new user in Druva inSync with the settings defined in this API.
- [Get user information using userID](https://developer.druva.com/reference/get_usermanagement-v1-users-userid.md): Returns information about a particular user in Druva inSync using the userID.
- [Update user information using userID](https://developer.druva.com/reference/patch_usermanagement-v1-users-userid.md): Use this API to update username, profile, and storage region of an existing user.
- [Delete a user](https://developer.druva.com/reference/delete_usermanagement-v1-users-userid.md): Deletes a user in the system. When you delete a user:  1. All the user data (restore points) is deleted.  2. If the user that is being deleted has shared data with guest users, this data is also deleted.  3. All devices of the user will get deleted, and all the active and preserved licenses that the user was consuming will be freed up.  4. You can roll back the deleted user from Rollback Actions until the rollback window lapses.  5. After the rollback window lapses, the user will be deleted permanently. For more information, see <a href=https://docs.druva.com/Cyber_Resilience/Rollback_Actions>Rollback Actions</a>.
- [Reset password for a user](https://developer.druva.com/reference/post_usermanagement-v1-users-userid-resetpassword.md): Resets the password for the user identified using the userID. inSync sends an email with a password reset link to the user.
- [Preserve a user](https://developer.druva.com/reference/post_usermanagement-v1-users-userid-preserve.md): Preserves a user in Druva inSync. When you preserve a user:     1) Backups from the user's device are stopped and the user status changes to Preserved.     2) inSync retains the user's data backups as long as the user is Preserved.     3) If not activated again, the preserved user is later deleted from inSync after the duration specified in the  Auto-Delete Preserved User settings of the user's profile.
- [Activate a user](https://developer.druva.com/reference/post_usermanagement-v1-users-userid-activate.md): Activates an already preserved user.  When you activate a user:     1) The user status would change from Preserved to Active.     2) State of all devices assigned to this user would change from Disabled to Enabled.     3) Backups from the user's device(s) would resume as per the configuration.     4) Before activating a user, if a user has consumed, for example, one Endpoints preserved license, then post-activation one Endpoints preserved license is freed up and one Endpoints active license is consumed (the same rationale applies to all workloads).     5) The license state of all the workloads associated with this user would change from Preserved to Active only if the user has Active licenses available for all the associated workloads.  For example, consider this scenario wherein you are trying to activate a user who has consumed one Endpoints preserved license, one Microsoft 365 preserved license, and one Google Workspace preserved license, but the user has only one Microsoft 365 Active license and one Google Workspace Active license available, and Endpoints Active license is not available, then: 	a. the user activation would fail, as there is no active Endpoints license available. 	b. the user will remain in a preserved state, and the license state of Microsoft 365, Google Workspace, and Endpoints would continue to remain in the preserved state.
- [Download AuthKey](https://developer.druva.com/reference/get_usermanagement-v1-users-userid-download-user-auth-key.md): Downloads the authentication key for users to replace or add a new device
- [List all profiles](https://developer.druva.com/reference/get_profilemanagement-v1-profiles.md): Returns a list of all the profiles configured in Druva inSync.
- [Get profile information](https://developer.druva.com/reference/get_profilemanagement-v1-profiles-profileid.md): Returns the profile configuration details using the profileID.
- [List all devices - v1](https://developer.druva.com/reference/get_endpoints-v1-devices.md): Returns information about all the user devices protected using Druva inSync.
- [Get device information - v1](https://developer.druva.com/reference/get_endpoints-v1-devices-deviceid.md): Returns device information using deviceID.
- [Delete a device.](https://developer.druva.com/reference/delete_endpoints-v1-devices-deviceid.md): Deletes a device in the system. When you delete a device:  1) All the device data (restore points) is deleted.  2) You can roll back the deleted device from Rollback Actions until the rollback window lapses.  3) After the rollback window lapses, the device will be deleted permanently. For more information, see <a href=https://docs.druva.com/Cyber_Resilience/Rollback_Actions>Rollback Actions</a>.
- [Disable a device](https://developer.druva.com/reference/post_endpoints-v1-devices-deviceid-disable.md): Disables a user device. Once disabled, the data backup from the device stops, and the user can no longer restore data to that same device. The data of disabled device is available in inSync and can be restored to different devices belonging to the same user, either by the user or an administrator.
- [Enable a device](https://developer.druva.com/reference/post_endpoints-v1-devices-deviceid-enable.md): Enables a user's device. After the device is enabled, the user of the selected device can start taking its backup and restore.
- [Create device mapping](https://developer.druva.com/reference/post_endpoints-v1-devicemappings.md): Creates a secure user-to-device mapping to perform a mass deployment in a non-AD/LDAP environment or perform bulk replace of devices. The user-to-device mapping ensures controlled device and user activation of inSync client and prevents addition of rogue or unauthorized devices to inSync.
- [List device mapping](https://developer.druva.com/reference/get_endpoints-v1-devicemappings.md): Returns a list of user-to-device mapping created to perform a mass deployment in a non-AD/LDAP environment or perform bulk replace of devices.
- [Delete device mapping](https://developer.druva.com/reference/delete_endpoints-v1-devicemappings-mappingid.md): Permanently deletes a user-to-device mapping created for mass deployment.
- [Decommission a device](https://developer.druva.com/reference/post_endpoints-v1-devices-deviceid-decommission.md): Decommission the device. Decommissioning a laptop or desktop allows you to securely wipe out data from all folders that inSync protects, which includes backup folders and inSync Share data. This is helpful in scenarios where devices are stolen or lost and you want to wipe out critical data from a device.
- [Upgrade inSync Client on a device](https://developer.druva.com/reference/post_endpoints-v1-devices-deviceid-upgradeclient.md): Upgrade inSync Client to its latest version on a user device. The inSync Client is upgraded only if a higher version is available.

- [Initiate a restore activity](https://developer.druva.com/reference/post_endpoints-v1-restores.md): Creates a data restore request and provides the option to scan the data for malware or viruses before restoring to the desired location on the target device.  You can either restore the user's data to the same device from which it was backed up or to a different device registered with inSync.  You can restore the data ONLY from the most recent snapshot to the target device.  You can initiate multiple restore activities, which may be consolidated into a single activity based on the inSync Client version; appropriate status is displayed for each activity.
